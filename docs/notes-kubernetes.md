- **Base recréée :** l’IP est passée de `10.42.0.12` à `10.42.0.14`, ce qui a nécessité de modifier `DB_HOST` et de recréer le Pod API. Sans volume persistant, la suppression du Pod PostgreSQL entraîne la perte des tâches. Un Service fournirait une adresse stable ; un volume persistant conserverait les données.
- **Pod API supprimé :** un Pod seul n’est pas remplacé automatiquement après sa suppression : il faut réappliquer le manifeste. Un Deployment, via son ReplicaSet, maintiendrait le nombre de Pods souhaité.
- **Processus API arrêté :** les logs confirment un arrêt propre sur `SIGTERM`. La politique par défaut `restartPolicy: Always` permet au kubelet de redémarrer le conteneur dans le même Pod, avec une augmentation de `RESTARTS`. Comme une politique de redémarrage Docker, elle relance le conteneur mais ne remplace pas un Pod supprimé.
